# 三模协同 · 并发编排规范（concurrency-guide）

> 版本：2026-08-15（方向师 gpt-5.4 独立总评估通过，推荐"先规范后实战再择机代码化"）
> 状态：**规范就绪，未代码化，且尚未经真实任务实战验证**（按评估：缺的不是并发能力，是使用规则；DSH 原生已有 subagent 后台/parallel/文件域）
> ⚠️ 当前运行模式为"父对话=架构+执行"（架构合一复审设计待验证）——本规范假设"方向师唯一总控 + N 架构师扇出"，**待真实任务验证该模式后再按本规范扇出**
> 原则：并发是特权，不是默认；先可判定是否值得并发，再谈如何并发。

---

## 〇、适用与总则

- 目标：大型项目时间从"串行 N 轮"降为"并行 1-2 波"（大型项目看时间不看 token）
- 不适用：强耦合、依赖链长、共享文件多、聚合返工代价大的任务——坚持串行
- 角色定位（评估收窄）：
  - **方向师（唯一，不并发）**：技术拆解、并发策略、终审裁决；只做三件事（定义目标边界/划分并发单元/统一验收取舍），不下沉代写实现细节
  - **父对话（甲方）**：承接用户意图、维持上下文、组织最终对外表达；不直接改技术拆解规则，只对"是否符合用户真实目标"把关
  - **架构师/执行层（扇出并发）**：**每路 = 一个架构师 + 一个执行者（独立三模协同）——并发 N 路则生成 N 个架构师**，每个架构师配执行者、各管一路、互不共享（防串行瓶颈，防"架构师只设计整体、执行者全并行"的误解）。任务规模小或合并模式下，可架构执行合一（每路一个架构师兼执行）。

## 一、并发准入表（方向师扇出前逐条回答，多数满足才并发）

| # | 问题 | 满足 |
|---|---|---|
| 1 | 能否按边界切成独立产物 | ☐ |
| 2 | 跨路共享文件少 | ☐ |
| 3 | 依赖链短 | ☐ |
| 4 | 每路都能独立验证 | ☐ |
| 5 | 聚合点有限 | ☐ |
| 6 | 返工代价可控 | ☐ |

≥4 项满足才并发；否则串行。

## 二、标准子任务卡片格式（每路必须包含）

```
目标：
边界（文件域/模块域所有权，禁改区）：
输入（含依赖方提供的接口）：
输出（产物/证据位置）：
依赖（分类见三）：
验收标准（可验证的具体断言）：
回传格式（见五）：
```

## 三、依赖分类（非仅"有/无"）

| 类型 | 含义 | 能否同波 |
|---|---|---|
| `none` | 无依赖 | ✅ 可并行 |
| `read-after` | 需读某路产物后才能做 | ⚠️ 下一波 |
| `interface-needed` | 依赖某路定义的接口 | ⚠️ 先定接口契约再并行 |
| `shared-file` | 共享文件（如全局配置/入口/公共类型） | ❌ 单点写入，聚合阶段处理 |
| `final-merge-only` | 只在最终合并时交互 | ✅ 可并行 |

## 四、扇出协议

- 用 DSH 原生 `subagent`（`run_in_background: true`）一次消息扇出 N 路，或 `workflow.parallel()`
- 每路只改自己边界内文件；共享文件显式标记"聚合阶段处理"
- 依赖方不能改被依赖方内部实现，只能提接口需求
- per-call 模型：**不作为并发 worker**（禁止被扇出）；可作并发前拆解者/并发后裁决者，不参与循环评审

## 五、回传摘要（结构化，防上下文爆炸）

每路回传固定五字段，限长，证据按引用挂载不直塞：
```
目标达成情况：
改动点（文件+简述）：
风险/未决项：
验证结果（真实证据，禁"理论上没问题"）：
依赖方所需接口/变更通知：
```
完成状态三档（禁二元）：
- `已完成且已验证`
- `已完成但待依赖验证`
- `已实现但存在未解风险`

## 六、审阅链路（双层，防重复审查）

1. **每路自审**（本路架构师复核）：本路需求漏读、接口假设错、文件越界、测试遗漏
2. **聚合统一终审**（方向师）：聚焦三件事，**不重查细节**——
   - 路间依赖是否闭合
   - 产物组合后是否满足最初目标
   - 有无系统级副作用/规范漂移

## 七、集体幻觉防线（最危险，必须设）

- 扇出前方向师明确"已确认事实 vs 待验证假设"
- 每路回传区分"我确认的"与"我继承假设的"
- 聚合终审单独检查"共享前提是否被验证"
- **设独立挑战位**：至少一个视角专门审前提本身，不向下执行；**挑战位由 N 路中某路架构师兼任或方向师指派，不额外增加架构师数量**

## 八、代码化门槛（将来，非现在）

同一并发规范在多个真实任务重复使用、任务卡片字段/依赖分类/摘要格式稳定、确实存在重复机械劳动时，才把"发任务模板/回传摘要模板/聚合视图"等**稳定部分**代码化；代码只做辅助执行，不做替代判断。

## 九、与本项目其他机制的衔接

- 本规范是 #4 变更安全（草案）在真实并发场景的**落地指引**：文件域所有权=changeDomains 约定；共享文件单点写入=租约思想的简化版
- 审阅链路复用两级闸门：每路自审≈架构复审，聚合终审≈方向师终审（reject 仍回执行修正）
- 与 #6（草案）衔接：并发时若某路模型出问题，按简单解法处理（父对话核查/换模型），不依赖未接线的升级链
